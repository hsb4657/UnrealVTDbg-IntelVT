# 稳定性优化与蓝屏风险复查

日期：2026-11-25。本文对应当前未提交源码，接续第 26 篇的失败路径修复。

## 结论与使用限制

按退出流程、日志、Root 回收、只读广播、EPT 分配的顺序完成修改，再复查初始化失败、Hook 撤销、资源复用和退出路径。发现了可导致空指针调用、执行错误指令、Root 死锁或读取无效页面的具体问题，并实施修复或保守阻断。

这不是“已验证不会蓝屏”的结论。当前运行环境为 macOS，没有执行 Windows/WDK 全量构建、Driver Verifier 或 Intel VMX 实机测试。

**PspExitThread 的安全热卸载尚未完成。** 此函数不返回；运行状态引用归零，不能证明线程已经离开驱动代码和跳板。现阶段在安装该 Hook 前禁用 Dbgk 驱动的 `DriverUnload`，后端也会保留该会话的驱动。默认全选包含此项，因此通常需要重启系统才能完全回收驱动；安装到此项后发生失败，也可能需要重启。此保护不能通过强制卸载绕过。没有选择该项的会话仍按原依赖顺序尝试停止，停止失败时保留 VT。

**跳板尚未实现完整指令重定位。** 对相对跳转、相对调用、RIP/EIP 相对寻址及尚未支持的编码，改为拒绝安装并回滚。因此某些 Windows Build 的指定 Hook 可能无法启用；这是明确的兼容性限制。

## 五项优化

### 1. 退出、心跳和驱动依赖

- 增加 `Shutdown_F3`（序号 6）和 `SessionActive_F3`（序号 7），原五个序号保持不变。新 UI 要求七个接口，不能混用旧后端 DLL。
- 心跳由退出事件唤醒，五分钟等待可立即中断；不再分离线程，也不再通过 `exit(0)` 结束宿主。正在进行的同步网络请求仍需等待现有网络超时，不使用强杀线程。
- 心跳失败撤销会话就绪状态、停止接收启动请求，并尝试受控清理；终止型 Hook 会话保留驱动并记录原因。
- 跟踪调试器启动线程，关闭 DLL 前先等待这些线程退出；不在 DllMain 中等待。
- IOCTL 和设备句柄关闭使用同一把锁，避免关闭仍在使用的句柄。
- 仅 `SERVICE_STOPPED` 或服务不存在算停止完成；开始/停止中的状态不再被误认为已停止。
- 先确认 `UnrealDevice` 和兼容的 `BACDevice` 停止，再处理 `VT_Driver`。任一消费者停止失败或状态查询失败，均保留 VT。

### 2. 日志

- 生产线程只格式化并入队；后台线程每约 100 ms 或累计 256 KiB 批量写入，文件保持打开。
- UI 与磁盘各自限制为最多 5,000 条、约 4 MiB；单条输入截断至 32,768 个字符。磁盘队列超额会累计丢弃计数，随后写入说明。
- 运行中达到约 8 MiB 即轮转为 `WinUI.previous.log`；正常退出等待最后一批写入和 flush。
- 写入/轮转失败向调试输出报告；文件系统错误、进程强杀或断电不属于“保证落盘”的范围。

### 3. VMX Root 资源回收

- 原池申请、释放均可能在 Root 调用 `KeAcquireSpinLock`；如果 VM-exit 打断了同核持锁者，就可能无法取得进展。
- 改为只追加、运行期间不删除的元数据索引：按用途查找可用对象，按地址哈希查找归还对象，通过原子状态转移取得所有权。
- 状态为 `FREE → BUSY → DIRTY → CLEANING → FREE`。Root 归还仅标记 DIRTY；PASSIVE 系统线程清零后再发布 FREE，避免未清理对象被复用。
- 分配和发布仍由现有单发布者门控串行化；元数据只在所有 vCPU 停止、补池线程退出后释放。
- 缓存池缓冲区的物理地址，split/fake page 路径不再为这些缓冲区调用 Windows 物理地址查询接口。
- retired 函数、页面单遍扫描，移除前保存 next；全量取消 Hook 不再每移除一页就重复扫描所有活动页。
- 可执行跳板仍不在普通 retired 回收中清零或复用。终止型调用涉及的卸载风险通过禁止热卸载处理，没有靠泄漏已卸载驱动的池来规避。

### 4. 只读跨核查询

只读查询仍遍历远端 EPT 链表，引用计数并不能保护“读到节点指针、尚未增加引用”这个窗口。因此保留读取前后的两次全核同步，只去掉 `SignalDpcDone` 隐含的第三次重复屏障，直接报告本核 DPC 完成。

这不是无广播读取或无锁快照实现。后续若要取消全核同步，必须先建立明确的快照或节点生命周期协议。

### 5. EPT 页表分配

- EPT 主结构保持原有 1,025 页布局，覆盖范围和内存类型策略不变。
- 改为大于一页的非分页池分配。Windows 对此提供虚拟页对齐；每张硬件表独占一页，各入口分别查询该页物理地址，因此不需要整块约 4 MiB 物理连续。
- 为 PML4/PML3/PML2 偏移增加编译期对齐检查，并将所有成功/失败释放路径配对为 `free_pool`。
- VMXON、位图和其他仍依赖原分配方式的对象没有批量更换分配器。这一项减少连续内存压力，不减少 EPT 表本身的页数。

## 复查发现与处理

1. **取消 Hook 后立即清空 Original 指针。** 已进入回调的线程仍可能调用它。保留原指针供在途调用完成，重试只能发生在状态回收后。
2. **终止型函数泄漏运行计数。** PspExitThread 不会执行 C++ 析构，原计数可能永久不归零。最后一次状态访问后显式释放守卫，并禁止该 Hook 会话热卸载，不能把“释放计数”当作“代码已退出”。
3. **IOCTL 过早报告退出。** 将计数归还移至请求完成后；卸载先排空请求再删除设备。
4. **LDE 先越界读取、后校验长度。** 将页内最多 15 字节复制到带填充的局部缓冲再解码，拒绝跨页/过长/失败结果。测试使用不可访问的相邻页验证边界，真实汇编解码器仍需 Windows 验证。
5. **复制跳板指令不重定位。** 加入保守的已知编码检查，拒绝位置相关和未知指令。辅助覆盖但不生成原函数跳板的路径仍可只检查指令边界。
6. **目标代码页未明确锁定。** 在广播安装前使用 MDL 锁页，按 PFN 去重；广播失败可能已有部分 CPU 安装成功，因此保持锁页直到撤销 Hook、排空运行调用后统一释放。锁页失败直接返回失败。
7. **Win10 回滚忽略回调清理失败。** 清理失败时保留锁页和驱动，禁止热卸载并拒绝后续 IOCTL；不再假定状态已经安全排空。
8. **Root 直接读取目标虚拟地址，撤销时再次读取原代码。** 安装时按目标 CR3 解析物理地址，通过已有受保护的物理映射拷贝保存驻留原指令快照；解码、跳板构造和恢复均使用快照。VMCALL Hook 不再忽略传入的目标 CR3。单项撤销按驻留记录中的完整 VA 查找，不重新解引用可能失效的目标 VA。

## 本机验证

运行：`python3 -m unittest discover -s tests -v`。22 项测试全部通过，无跳过；保留原有 CRLF 的空白检查通过。

测试提取实际生产函数体，在 C++17 环境中用 Windows API 替身执行；部分检查直接编译共享策略头。覆盖原有九项失败路径，以及依赖停止失败、心跳退出/失败、异步日志与运行中轮转、4,000 次并发池申请归还、分配中途失败、立即清零下的 retired 遍历、活引用保护、页边界、拒绝重定位指令、代码快照、锁页失败/去重/释放和终止型 Hook 的热卸载阻断。

这些测试不能证明 Windows IRQL、SEH、内核指令执行或真实多核时序正确。EPT 测试检查布局与分配/释放配对，不代表硬件页表遍历已经验证。仓库原先记录的 2026-10-17 Windows 构建结果也不适用于本次新增修改。

## 尚需 Windows 验证

- Debug/Release x64 的六项目全量构建，确认新七个 DLL 导出及打包一致。
- Win10/Win11 实际 Build 上选择全部关闭、分组启用、逐项失败回滚；特别检查指令检查新增的拒绝情况。
- 锁页配合内存压力和 Driver Verifier；不得出现仍有 EPT 引用时提前解锁。
- 未启用终止型 Hook 时，反复进入/退出以及并发断点读取、移除、目标进程退出；验证设备、池、MDL、回调、VMXOFF 顺序。
- 启用 PspExitThread 时确认普通停止被拒绝、VT 被保留，重启后服务可重新加载。未来恢复安全热卸载需要独立设计并证明执行流已离开驱动和跳板。
- 高核数、混合架构、不同物理地址宽度、内存压力下 EPT 建表和 INVEPT；现有高地址映射及 MTRR 策略本轮未重新设计。

复查没有把“当前用例通过”扩展为“整个项目不存在致命漏洞”。尤其是系统私有符号/偏移、尚未建立快照的远端 EPT 链表和真实执行流退出，仍属于必须用目标系统验证的部分。
