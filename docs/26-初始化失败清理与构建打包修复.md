# 初始化失败清理与构建打包修复

日期：2026-11-24。

## 修复内容

1. **Win11 保护回调生命周期**：`SetProcessCallbacks`、`InitProtect` 返回注册状态；注册失败时 DriverEntry 返回失败。注册成功但设备创建失败时，DriverEntry 主动注销回调。注销后清空句柄，重复清理不再断言或重复注销。Win10 共用接口同步更新，其原来未启用的保护注册路径保持不启用。
2. **用户态 Hook 安装失败**：安装在首个失败处停止；只有全部安装成功才进入已安装状态。运行线程在失败时撤销已提交的项，按相反顺序清理。撤销失败的项保留记录、DLL 引用和驱动连接，不再误报清理成功或释放仍被 Hook 引用的模块。初始化失败不发送 ready 事件。
3. **内核 Hook 安装失败**：Win10 的 36 项和 Win11 的 34 项可选入口向上传递安装结果；用户选中的入口都必须成功。维持原安装顺序和平台差异，不选中的项不参与成功判定。选中项失败时调用现有全核撤销路径，包含失败广播中已经成功安装的部分，再清理 Dbgk 状态。初始化返回 `INIT_SYMBOLS_STATUS_EPT_HOOK`（`0xE107`），后端打印状态码并返回失败。现有撤销路径无法安全完成时的致命错误策略保持不变。
4. **辅助补丁状态**：PspExitThread 内部比较指令补丁的安装结果也向上传递；反汇编长度为零时返回失败，避免把非零函数地址加零误判成有效后继地址。
5. **TL 请求结果**：无效 PID 或自身 PID 返回 FALSE，并设置 `ERROR_INVALID_PARAMETER`；其它请求返回真实 IOCTL 结果。UI 原有失败处理能够据此正确显示结果。
6. **构建顺序与打包来源**：解决方案将五个后端工程设为 UI 的构建依赖，后端全部完成后才进入 UI 打包。直接构建 UI 的 `.vcxproj` 仍不构建后端。解决方案 x64 打包缺少必需文件时失败；同名文件优先使用解决方案输出，不再由项目目录的旧文件覆盖，也不再从 `bin` 通配复制历史文件到应用目录。

## 已执行验证

运行 `python3 -m unittest discover -s tests -v`，9 个测试全部通过，没有跳过。测试在 macOS 使用 Clang 和 Mono MSBuild 执行。

- 针对用户态 19 个 Hook，分别模拟每个位置安装失败及撤销失败；检查返回状态、撤销顺序、重试清理、句柄保留及重复初始化行为。
- 检查运行线程在初始化/握手/ready 事件失败时是否保留或释放模块引用。
- 分别模拟 Win10 36 项、Win11 34 项内核安装失败，确认失败返回和回滚；检查全部关闭及单项选择。
- 编译并执行实际选中 Hook 包装函数，检查未初始化、缺少符号、底层返回失败以及 PspExitThread 辅助补丁失败的传播。
- 检查初始化失败返回 `0xE107`、清理状态及重试成功。
- 模拟 Win11 回调注册失败和设备创建失败；检查注销次数与幂等性。
- 检查 TL 非法输入、请求失败和请求成功的返回结果。
- 检查解决方案的五项依赖；用临时文件执行实际 StageRuntime 目标，确认新文件优先、缺文件失败及独立 UI 构建回退来源。

这些是实际函数体配合 API 替身的控制流测试，以及独立执行实际 MSBuild 打包目标；不模拟真实并发、Windows 对象管理器、Detours、EPT 或 VMX 硬件。

## Windows 上仍需验证

1. VS2022 + WDK/SDK 环境下构建 `Debug|x64`、`Release|x64`；确认两套驱动、Hook 和后端 DLL 声明/链接一致。
2. 清空输出后运行解决方案 `/m /t:Build`，确认五个后端先于 UI 完成，应用根目录和 `bin` 中产物一致。再单独构建 UI 项目，确认没有重新构建后端。
3. 在测试驱动中注入回调注册失败、设备/符号链接创建失败，确认加载失败后无遗留注册，随后可正常重新加载。
4. 在 Hook 安装和全核广播路径注入部分失败，确认不报告就绪，撤销覆盖已成功的处理器；再次初始化可成功。
5. 完成加载、附加、软件/硬件断点、单步、删除断点、分离与卸载回归，检查蓝屏、卡死及残留回调。

当前环境未执行 Windows 全量编译或实机 VT 测试。
